# Web (Nuxt control plane)

The web app is a **pure control plane**: configure, issue, observe. It never uploads or parses documents — the data plane is API/MCP only. It does *render* a finished result (the markdown a job produced), because reading what came back is observation, not a second data plane.

## Stack

Nuxt (latest stable) + TypeScript + `@nuxtjs/i18n` (en, zh-TW; en is the source catalog), pnpm. No UI framework and no CSS framework — hand-rolled primitives over the design tokens in `app/assets/css/main.css`, styled in each SFC's own scoped block. There is no Tailwind, no utility layer, and no second component library.

## Design system — Graphite

An editorial system, not a card dashboard: serif headings, hairline rules instead of card borders, cool-gray paper, and a single steel-blue accent.

- **Tokens** in `app/assets/css/main.css`, as plain custom properties on `:root` — this app's one convention. The color ramp is paper / paper-sunken / rail / rail-active / desk for surfaces, ink / ink-soft / muted / faint for text, line / line-soft / line-strong / hair / edge for rules, and one `--accent`. Spacing, radius, type, control heights and the table rhythm are tokens too: a raw hex, a raw `padding: 13px` or a raw `font-size: 15px` inside a component is the same class of bug. Every color is declared in both `:root` theme blocks and nothing outside them names a color; the light values are the design's, the dark block is a derived inversion of the same ramp.
- **Accent discipline is the core rule.** Steel blue appears only on data and the controls that commit it: cost figures, usage meters, the brand mark, primary buttons, the succeeded status dot, active page markers in the result viewer, the active locale's underline, and focus rings. Never on headings, borders, backgrounds or decoration.
- **Type**: `Source Serif 4` (Google Fonts, `opsz 8..60`, fallback Georgia) for page titles, panel headings, metrics and the result viewer's headings; the system sans stack — `Noto Sans TC` included, the app is bilingual — for UI and body; `ui-monospace` for model ids, key prefixes, URLs, bboxes and code. Every figure carries `font-variant-numeric: tabular-nums`.
- **Geometry**: 3px radius on controls, 0 on panels and dialogs. 1px borders. Exactly one shadow, on dialogs and the mobile drawer. Control heights 36 / 34 / 30 / 26px, all from tokens.
- **Two scroll axes on every screen.** One layout, `default`: a non-scrolling `100dvh` grid of a 236px sidebar and a content region. The content region is itself a grid of a `clamp(200px, 20vw, 320px)` left rail — eyebrow, serif title, then either headline figures or the screen's primary action, scrolling on its own — and a right data region, which is either one full-height scrolling panel or a split of two independently scrolling ones (the lower takes `--paper-sunken`, and the two are divided by a 1px rule, not a gap). Nothing puts a whole screen on one scrollbar. `min-width: 0` on the grid tracks and the flex panels is load-bearing: without it a table forces the region wider than the viewport instead of scrolling inside its panel.
- Below 900px the rail collapses above the data region and the sidebar goes behind a focus-trapped drawer. The sign-in page is full-bleed and owns its own frame (`layout: false`), sharing tokens only.
- **Primitives** in `app/components/ui/`: `Panel` (header + independently scrolling body, no border/radius/shadow, optional `sunken`), `PageHeader` (the rail's eyebrow + serif title block), `DataTable` (the only table markup — `min-width` + nowrap so it scrolls in place, sticky header on an inset rule, per-column alignment, no border on the last row), `Modal` (square, and able to host a grid-bodied dialog as well as a form), `Button` (accent / secondary / ghost / danger, `icon-only`, three sizes), `TextInput`, `Select`, `Field` (label-less with an `aria-label` where the design has no visible label), `CopyField`, `CopyButton`, `UsageBar` (a 3px square accent meter), `StatusDot`, `EmptyState`, `Banner`, `Skeleton`, `Spinner`, `ConfirmDialog`, `Icon`. There is no `Card` and no `Badge`: the design has no cards, and a count is panel-header meta text.
- **Icons** are Lucide paths on a 24 grid at stroke 1.75, inlined in `Icon.vue` — never a package, never a remote sprite, never inline SVG at a call site. Icon-only controls carry `label` (= aria-label + tooltip); destructive actions keep their visible word.
- **Motion**: 120–160ms on color and background only. No hover elevation anywhere — hover is a text-color shift to the accent on links and a background shift on nav and list rows.
- Icons ship as three files in `public/`: `favicon.svg` (the source mark — the `scan-text` glyph reversed out of an accent rounded square), `favicon.ico` (16/32/48, generated from it) and `apple-touch-icon.png` (180). All three are declared in `nuxt.config.ts`, and the FastAPI consent page declares them too. The `.ico` is not redundant: clients that do not take SVG — connector webviews among them — request `/favicon.ico`, and when that answers a blank placeholder they fall back to whatever icon they already hold for the parent domain.

## Result viewer

Opened from a filename on `/jobs`, over `GET /api/jobs/{id}/result`. A grid dialog whose header carries the filename, the `model · N pages · bbox format` line, and a Markdown / JSON toggle.

- **Markdown** is the default tab: a page rail on the left (one button per parsed page, with its figure count) beside one continuous scroll of every page. `app/lib/markdown.ts` turns the result's markdown into ordered blocks per page — the `<!-- page: N -->` markers split pages, and within a page `##`/`###` headings, GFM tables in either form (the outer pipes are optional, so the separator row is what identifies one), `-`/`1.` lists including wrapped items and the number they start at, `$$` display-math and fenced code blocks (whose line breaks and indentation are their content), `![fig](sightread://p…)` placeholders with the caption on the next line, and paragraphs each become a block. Parsing is client-side because the API returns the document as one markdown string (docs/parsing.md § Page markers).
- A job whose pages partly failed still finishes as `succeeded` and simply omits them, so the markdown view leads with a banner naming the missing pages when `result.errors` is non-empty. A degraded document must not read as a complete one.
- **Known limitation**: the parser is flat. A nested list renders as one level — the items survive, the hierarchy does not — and inline emphasis is shown as its source characters. Both are deliberate: this reads a known set of block shapes rather than implementing GFM, and every shape added so far has revealed the next one it does not know. Rendering the result through a real GFM parser is the alternative, and it is a dependency and sanitisation decision of its own rather than something to bolt on here.
- Scrolling the document updates the rail: the active page is the last section whose top has passed a reading line 72px below the pane's top edge. Clicking a page sets the pane's `scrollTop` from the section's `offsetTop` and suppresses the scroll-driven update briefly, so the click's target wins.
- **Figures render as a placeholder**, not an image, and this is a known gap rather than a design choice: the parse pipeline does not persist cropped figure images yet, so there is no URL to show. The caption keeps the figure name and its bbox. When the backend starts storing crops, an `<img>` replaces the placeholder in the same slot.
- **JSON** replaces the body with the pretty-printed result on the sunken surface.

## Rules

- Auth state via `GET /api/me`; unauthenticated → sign-in page; signed-in on `/` → `/dashboard` (locale-aware, client-side). Login is a plain link to `/api/auth/login` (server redirect flow, no client OAuth).
- The web app calls only `/api/*` (+ `GET /v1/models`, `GET /v1/profiles` which are safe reads). Session cookie, `credentials: include`, custom `X-Requested-With` header on mutations (CSRF pairing with SameSite=Lax).
- Frontend renders only what the backend returns — empty states are real states, never fabricated sample data.
- Uploads never pass through Nuxt/Node — there is no upload UI; `curl`/connector instructions live on `/keys` and `/connect`.
- Every control has a visible focus ring: a 2px accent outline at 2px offset, never removed, never replaced per component.
- i18n: every user-visible string goes through the catalog; en and zh-TW ship together. Locale switching lives on the sign-in footer and, once signed in, in Settings — the shell's account row is a plain row, not a menu. The sign-in link passes the locale to `/api/auth/login`, which returns the visitor to the same one ([auth.md](./auth.md) § 1).
